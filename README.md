# 喝在西皮（huish798-app）

> 一款以**豆包（Doubao）AI（Vibe Coding，AI 辅助协作编程）**方式开发的校园饮水服务客户端。它把开源项目「掌上华电」的取水部分独立出来，重新设计了图标与色调，并尝试进一步液态玻璃化（效果一般，未完全成功），在消费记录中加入了跳转至相应设备的功能。应用对接**云哆啦科技有限公司**的 ilife / CLOUDORA 饮水设备接口，支持扫码 / 手动添加设备、一键取水、消费记录查看与设备分组管理等能力。

## 📖 项目缘起

本项目源于校园饮水服务中的实际使用痛点，也源于对开源社区的一次学习与致敬。

- **官方客户端的不足**：官方「慧生活798」App 广告频繁（设置中的"关闭广告 14 天"入口，在实际使用中往往隔几次操作便需重新关闭）；取水路径繁琐，常需多次跳转才能回到打水页面。
- **开源项目 huish798 的使用与局限**：作者在**几个月前**于 KimiStore 上发现了开源项目 **huish798**，并持续使用了**几个月**，从中学习取水模块的实现。huish798 在界面交互上也有一些不便之处：扫码按钮位置不够顺手、添加设备后列表顺序随机、难以快速找到刚添加的设备。这些问题当时作者便想过交给 AI 来优化，但彼时既缺乏相关经验、能力也不足，最终搁置。后来因服务端收紧协议（版本门禁），huish798 无法继续使用，只能回归官方客户端。
- **替代方案的摸索**：作者所在学校未统一发放水卡，需借助手机端解决取水问题。曾尝试 root、GKD、李跳跳等方案，但成本较高或需常驻后台且效果不理想；也曾尝试把官方 App 交给 AI 分析，但要真正推进还需脱壳、动态分析等经验，作者尚不具备，未能推进。
- **本项目的确立**：在再次寻找替代方案时，作者发现了界面清爽、操作便捷的「掌上华电」（Ncepu-Assistant）项目。适逢豆包（Doubao）等 AI 辅助编程工具降低了应用开发门槛，结合此前开发「CICP 教务查询」的经历，在室友的多次反馈与鼓励下，作者决定将「掌上华电」的**取水部分独立出来**，重设计图标与色调，尝试液态玻璃化，并在消费记录中加入跳转设备的功能——这就是「喝在西皮」。

**致谢与声明**：作者在此特别感谢 **huish798** 项目及其作者的无私分享，本项目的取水接口与核心逻辑参考了该项目的实现；同样感谢**「掌上华电」（Ncepu-Assistant）**项目——其界面清爽、操作逻辑便捷，恰好解决了作者之前一直想解决的问题（便捷地使用饮水服务），本项目界面与交互亦以其为参考。另外，应用名称「喝在西皮」由室长 **Tianze** 提供，应用图标由 **ChatGPT** 生成，一并致谢。

需要郑重说明的是，**本项目是纯粹的学习与交流项目，不包含任何商业目的，代码仅供学习参考**；使用时请遵守相关法律法规与学校规章制度。

## ✨ 功能特性

- **扫码 / 手动添加设备**：通过扫码或手动录入绑定饮水设备机位。
- **一键取水**：首页底部快捷入口，一键启动指定机位的取水操作。
- **消费记录查看**：账单按时间线展示，点击账单可跳回对应机位的操控界面。
- **设备分组管理**：按宿舍楼 / 楼层对设备进行分组与快捷筛选。
- **水蓝玻璃化 UI**：在掌上华电基础上重构了图标与色调，尝试对齐液态玻璃设计（效果一般，未完全成功），背景延伸至状态栏与底部导航栏。
- **NFC 预留通道**：预留了通过手机 NFC 一键启动对应饮水设备的能力（未接入，见「未达成功能」）。

## 🔧 环境要求与构建

- Flutter 3.x（需配置 Android SDK）
- 构建单架构 release APK：

```bash
export ANDROID_HOME=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk-17
export PATH="$JAVA_HOME/bin:$PATH"
flutter build apk --release --target-platform android-arm64
```

产物位于 `build/app/outputs/flutter-apk/app-release.apk`。

## 📜 开发历程

本项目以 **豆包（Doubao）AI（Vibe Coding，AI 辅助协作编程）** 方式完成：由人提出需求、AI 负责实现与打磨，形成"需求 → 生成 → 真机验证 → 修正"的闭环。每一轮都是一个完整版本的构建与交付，APK 均经真机安装验收。

这也是作者**第一次**尝试以 Vibe Coding 方式开发 **Flutter** 项目（此前仅用豆包制作过一个网页套壳的教务查询 App），本项目因此更偏向学习与尝试性质。

> **时间说明**：本项目的开发**并非持续进行**，而是跨多轮会话分段完成。若折算成持续开发，累计工作量约为 **4 小时左右**；其中约 **2 小时多**用于**第一次生成 App**（搭建 Flutter 工程、接入取水接口、产出首个可用版本）。首次生成时云端沙箱状况不佳（构建反复卡顿、Flutter daemon 在沙箱残留引发锁冲突、后台任务易被中断），导致首个版本未能一次构建成功，**新建对话后才成功构建出第一个可用版本**。

## 🚧 未达成功能

1. **反复取水后设备无法启动**：同一设备反复点击「开始取水」太多次后，会提示「当前设备正在使用」（-15）而无法启动。根因是客户端与服务端对设备状态的判定脱节（客户端显示"空闲"，服务端仍有独立占用判定）。已定位，修复方向（启动前先查状态、`stop` 补 `rcp=false`、`start` 补 `cnt=1`、错误码表补 `-15`）尚未实施。
2. **NFC 一键启动饮水设备**：已预留 NFC 服务通道，但尚未接入手机 NFC 一键启动对应设备的能力。

## 🧭 关于「刷积分」功能

本项目**不会加入**刷积分相关的功能，原因如下：

1. **需求已满足**：去除广告、优化取水体验，已经达到了作者的核心诉求；
2. **避免侵害官方利益**：刷积分本质上会绕过官方服务的运营规则，占用服务端资源、干扰正常的积分与运营体系，加大对服务提供方（云哆啦科技）正常利益的侵害——这与本项目"克制、学习、不越界"的定位相悖。

不过，作为 Vibe Coding 学习项目，刷积分也是一个值得探索的**实践方向**：如果你对此感兴趣，可以自行尝试实现（可参考 huish798 等项目源码），请在尊重服务方规则、合法合规的前提下探索。
